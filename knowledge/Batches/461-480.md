# Batch 461-480: Release candidate reliability

This batch establishes deterministic, named, instance-scoped fault injection that is rejected in production. Failure coverage holds database mutations, stored artifacts, scanner state, queued provider work, and leased worker work to truthful state transitions. Ambiguous external effects enter review.

`pnpm data:verify` is read only and reports structured invariant codes and entity identifiers. Restore validation requires an isolated target plus migration, accessibility, checksum, and invariant evidence. Four synthetic historical schema milestones feed the upgrade-only matrix; they contain no real personal data and make no claim about fields that did not exist at a milestone.

The `release-candidate` profile preserves strict security and private-cache behavior while selecting isolated deterministic providers. Production rejects those providers. A fictional stable-alias fixture supports identity, academic, coursework, document, reporting, and recovery lifecycle acceptance tests.

Run `pnpm test:release-candidate` for the composed reliability entry point. It covers fault and lifecycle suites, upgrade preservation, invariant verification, security, i18n, accessibility/browser journeys, container structure, load configuration, and database preflight when an isolated database URL is present.

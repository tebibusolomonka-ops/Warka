# Batch 181–200

The API now starts an opt-in backup scheduler independent of a browser. PostgreSQL advisory coordination prevents duplicate due work across instances. Scheduled task records retain safe status and bounded retry attempts. Backup verification, operational backup artifact retention, and non-destructive personal-data retention evaluation use this scheduler. Backup cleanup preserves metadata history and protects required verified backups and active rehearsals. Operators have scoped scheduler status, history, retry controls, and a React workspace; test-only deterministic ticks support browser journeys.

FileAsset stores metadata, purpose, checksum, status, and domain links without storing bytes in PostgreSQL. Local storage generates keys and rejects traversal; private S3-compatible storage uses the same interface. Uploads validate size, name, allowed MIME type, and signature; the quarantine state is a boundary for future scanning, not a claim of malware detection. File delivery is purpose-bound and server-mediated. File asset IDs and public verification references do not grant access.

Teachers can attach uploaded materials to controlled teaching contexts while links remain supported. Eligible students and guardians can access published materials according to current relationships. School administrators can manage a current raster logo. Official report cards and transcripts store separate PDF artifacts for each issued or corrected version, preserve immutable snapshots and historical assets, and keep authenticated downloads private. Operators see aggregate storage counts and bytes without student filenames.

Local PostgreSQL and Docker are unavailable in this workspace; migration deployment and browser execution depend on CI or a configured integration host. See [[Testing]], [[Security]], and [[KnownIssues]].

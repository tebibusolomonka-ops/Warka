# Batch 441–460: mobile and low-bandwidth reliability

Warka uses centralized fluid layout, stack, grid, sidebar, toolbar, semantic responsive table, touch target, and mobile form conventions. Mobile navigation renders the same authorized link model as desktop and manages focus. Low-bandwidth mode is an explicit account preference; network hints may suggest it but never save it automatically or change authorization or official calculations.

Browser offline state and server reachability are separate. Safe reads may retry, while mutations that fail ambiguously are never replayed blindly. Warka makes no claim of full offline synchronization.

The installable manifest contains only application metadata. The service worker uses a release-scoped Warka shell cache for named public shell assets and bypasses API and download paths. Activation removes only older Warka shell caches. Authenticated API responses remain `private, no-store`; private records and documents are never placed in offline cache.

`UploadSession` stores bounded metadata, ownership, school scope, progress, expiry, and controlled status in PostgreSQL; temporary chunks remain in configured file storage. Session identifiers do not grant access, cross-user and cross-school continuation is denied, chunk and total sizes are bounded, and assembly produces a checksum while leaving malware scan status pending. Browser clients retain file bytes only in the current `File` object.

HTTP Range parsing produces standards-based partial response metadata after normal file authorization and clean-state checks. Public verification does not grant document download or range access.

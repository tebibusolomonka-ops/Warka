# Batch 221–240

Transactional email now has durable delivery metadata, server-owned templates, a provider interface, a production SMTP adapter, and an outbox coordinated by the existing PostgreSQL scheduler. Recovery requests queue email while retaining neutral public responses; recovery tokens are short lived, single use, hashed at rest, and reconstructed only in memory for sending. Completed deliveries are not resent. Retries are bounded and reserved for known unavailable outcomes; ambiguous outcomes require operator review. Operations can inspect safe status and retry eligible deliveries, without arbitrary bulk sending.

User notification preferences choose in-app and email delivery by category. Account-security in-app notices remain mandatory. Only selected events route to minimal email summaries and authenticated application links. Daily and weekly digests are opt-in, skip empty windows, and use a unique user/window record to prevent duplicate sends. The self-service delivery API returns recent safe status only for the signed-in user. Controlled browser journeys cover recovery, notification links, digest deduplication, and cross-user denial when a dedicated PostgreSQL database is available.

The commit-220 formatting blocker was repaired first. Local PostgreSQL, Docker, and SMTP services were unavailable; final local and CI validation status belongs in the batch report. Production use requires deployed migrations, SMTP settings, the recovery derivation key, and the validated public app URL.

# Batch 321–340

Data-quality checks produce factual, non-destructive issues and runs. They never merge duplicate student candidates, infer dropout from missing re-enrollment, convert missing marks to zero, or compare historical issued documents with mutable current values as an error. No school quality score, ranking, or fraud score was added.

Existing reporting periods now define optional open, due, and close times. Readiness distinguishes blank, unknown, not reported, not applicable, and measured zero; it never submits automatically. Each explicit school submission creates an aggregate-only version with actor, timestamp, validation summary, and deterministic checksum. Resubmission follows a return with a reason and preserves all earlier versions. Bureau review accepts an explicit version or returns it without editing school values.

Append-only discrepancy notes retain version and author; bureau-internal notes are hidden from school reads. Regional checks emit factual issue codes and required-school coverage. Audited CSV exports contain only accepted aggregates with formula-safe cells, never raw student records. Deduplicated deadline notices use neutral wording and the existing notification preference and email scheduler. The school and bureau workspaces expose these scoped actions and histories.

Focused tests and Playwright discovery ran during development. Local PostgreSQL and Docker were unavailable, so database integration and live browser journeys require the final CI run. Legacy submissions can be backfilled only from their last stored snapshot, with no historical checksum; see [[KnownIssues]].
